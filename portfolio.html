Project Description

InstaRecipe is a full-stack web application designed to help users make quick, informed decisions about meal preparation by generating personalized recipe suggestions from ingredients they already have at home. The platform tackles two real-world problems: food waste — the USDA estimates 30–40% of the U.S. food supply is wasted annually — and the time people spend deciding what to cook, which averages 43 minutes per day according to a UK study.


The platform supports two user roles. Guest users can access the AI recommendation feature. Registered users unlock the full feature set: keyword and advanced filtered search, recipe upload with photos and step-by-step instructions, save-as-draft or publish workflow, community ratings and reviews, and a personalized favorites dashboard with suggestions based on past cuisine preferences. All recipes, user accounts, and images are managed through Supabase's PostgreSQL backend. Agustina contributed as frontend developer, building the user interface, login and registration system, and responsive layouts using React.js and CSS.

System Architecture

React.js handles all frontend rendering and state management. Supabase provides user authentication, the PostgreSQL recipe database, image file storage, and API endpoints. The OpenAI API is integrated to generate personalized recipe suggestions based on user-supplied ingredients, returning results in seconds.

Key Features

AI recipe generation from available ingredients · Keyword search with filters for meal type, diet, difficulty, cooking time, and rating · Recipe upload with title, description, photos, categorization, and instructions · Save-as-draft or publish workflow · Community ratings and reviews · Personalized favorites dashboard · Trending recipes section

Honorable Mention — 2026 Lincoln University Undergraduate Research Symposium

Codexia received a perfect score from the judges at the 2026 Lincoln University Undergraduate Research Symposium, earning an Honorable Mention for its innovative approach to accessible programming education and its demonstrated social impact for students with dyslexia.

Project Description

Computer science education presents a particular challenge for students with dyslexia. Standard coding platforms use dense, visually uniform text that increases cognitive load — research by Rosen et al. (2025) shows that dyslexic individuals re-read the same lines repeatedly and take significantly longer to process code. Codexia was built to remove these barriers through a web-based coding environment where accessibility is the core design principle, not an afterthought.


The platform allows users to write and execute JavaScript code directly in the browser, then adjust the visual presentation of that code — font family, font size, and color — to reduce cognitive load. When a student encounters an error or wants to understand how their code works, they can request an AI-generated explanation. The Google Gemini 2.5 Flash model is called through a FastAPI backend (which keeps API keys secure) and returns a structured, beginner-friendly explanation in a maximum of 6 plain-language steps. Every explanation is also available as audio through the Web Speech API, providing multimodal support. The platform also includes 60 practice coding problems stored in a JSON file, filterable by difficulty level.

System Architecture

HTML, CSS, and JavaScript power the frontend, managing the code editor, live CSS accessibility updates, and code execution via JavaScript's new Function(). FastAPI (Python) serves as the backend, applying the AI system prompt and forwarding requests to the Gemini API. The cleaned response is returned to the frontend for display and Text-to-Speech output.

AI Design Decisions

The Gemini 2.5 Flash model was selected after OpenAI access proved unavailable. The backend system prompt constrains responses to a maximum of 6 steps, uses simple vocabulary, avoids complex symbols, and follows a "Step 1, Step 2…" format — specifically designed to minimize cognitive overload for dyslexic learners.

Best Undergraduate Poster Award — Delaware Data Science Symposium 2025

This research was conducted as part of the DaMAD-ScientistCorps Summer Research Program (May–June 2025) under supervisor Dejene Dedefa, and was presented at the Delaware Data Science Symposium 2025, where it received the Best Undergraduate Poster Award for its rigorous methodology and real-world cybersecurity application.

Project Description

This project developed an end-to-end machine learning pipeline to classify emails as phishing or legitimate, working with a cleaned dataset of 49,628 labeled emails. The work focused on the full ML layer: feature engineering, model training and evaluation across supervised and unsupervised approaches, and final deployment into a working application.


Feature engineering produced 20+ phishing indicators, including link counts, suspicious keyword frequency (from a curated list of 20+ terms across 5 categories such as urgency, financial themes, and credential alerts), email body length, and sender domain analysis — notably, 99.8% of phishing emails used unknown sender domains. Email text was vectorized using TF-IDF limited to 300 features, then merged with the engineered features into a unified training set. Eight models were trained and evaluated: four supervised (Logistic Regression, Random Forest, SVM, KNN) and four unsupervised (Isolation Forest, Local Outlier Factor, KMeans, One-Class SVM). Supervised models far outperformed unsupervised ones, which suffered 50–60% accuracy and high false positives. The top three supervised models were serialized and integrated into a Tkinter desktop GUI with Gmail API connectivity for real-time email fetching and prediction.

Feature Engineering

Link counts (http/www occurrences) · Suspicious keyword frequency (20+ terms across 5 phishing categories) · Email body length · Sender domain classification — public, mismatched, or unknown · TF-IDF vectorization (top 300 features) on combined subject and body text · Feature matrix merged from engineered indicators and TF-IDF output

Deployment & GUI

Top 3 models serialized as .pk files alongside the TF-IDF vectorizer. A Tkinter GUI allows users to select a model, run the full pipeline or prediction only, view results in an interactive table, and display a confusion matrix. Gmail API integration fetches real emails via OAuth for live classification.
